# HabitatTrack API - Technical Spec

## 1. API Architecture
- **Framework:** FastAPI
- **Database:** Google Cloud Firestore (NoSQL Document Database)
- **Language:** Python 3.12+

## 2. Data Models


### 2.1 Property Model

#### Firestore Collection Name: `properties`

#### Fields:
| Field Name            | Data Type | Description                                                      | Constraints              |
|-----------------------|-----------|------------------------------------------------------------------|--------------------------|
| `id`                  | String    | Unique identifier for the property (auto-generated by Firestore) | Primary Key, Unique      |
| `first_line_address`  | String    | First line of the property's address                             | Required                 |
| `second_line_address` | String    | Second line of the property's address                            | Optional                 |
| `city_or_town`        | String    | City or town of the property's address                           | Required                 |
| `description`         | String    | Optional descriptive text about the property                     | Optional                 |
| `date_created`        | Timestamp | Date and time when the property record was created               | Auto-generated, Required |
| `date_last_updated`   | Timestamp | Date and time when the property record was last updated          | Auto-generated, Required |

### 2.2 Transaction Model

#### 2.2 Firestore Collection Name: `transactions`

#### Fields:
| Field Name               | Data Type | Description                                                                  | Constraints                                       |
|--------------------------|-----------|------------------------------------------------------------------------------|---------------------------------------------------|
| `id`                     | String    | Unique identifier for the property (auto-generated by Firestore)             | Primary Key, Unique                               |
| `transaction_type`       | String    | Type of transaction: "income" or "expense"                                   | Required, Enum ('income' or 'expense)             |
| `transation_category_id` | String    | ID of the associated transaction category (links to `transaction_categories) | Required, Foreign Key to `transaction_categories` |
| `amount`                 | Float     | Amount of the transaction                                                    | Required, Must be positive                        |
| `description`            | String    | Description of the transaction                                               | Optional                                          |
| `transaction_date`       | Timestamp | Date and time when the transaction took place                                | Required                                          |
| `property_id`            | String    | ID of the associated property (links to `properties` collection)             | Optional, Foreign Key to `properties`             |
| `date_created`           | Timestamp | Date and time when the transaction was recorded                              | Auto-generated, Required                          |


### 2.3 Transaction Category Model

#### Firestore Collection Name: `transaction_categories`

#### Fields:
| Field Name          | Data Type | Description                                                             | Constraints              |
|---------------------|-----------|-------------------------------------------------------------------------|--------------------------|
| `id`                | String    | Unique identifier for the category (auto-generated by Firestore)        | Primary Key, Unique      |
| `name`              | String    | Name of the transaction category (e.g. 'Rent Income' and 'Maintenance') | Required, Unique         |
| `description`       | String    | Optional descriptive text about the property                            | Optional                 |
| `date_created`      | Timestamp | Date and time when the category record was created                      | Auto-generated, Required |
| `date_last_updated` | Timestamp | Date and time when the category record was last updated                 | Auto-generated, Required |


### 3 API Endpoints

#### 3.1 Property Endpoints (`/properties`)
- `POST /properties`
  - **Description:** Create new property.
  - **Request Body:** `PropertyCreate` schemas (excluding `id`, `date_created`, `date_last_updated`).
  - **Response:** `Property` schemas (including `id`, `date_created`, `date_last_updated`).
  - **Status Code:** 201 Created, 400 Bad Request

- `GET /properties`
  - **Description:** Retrieve a list of all properties.
  - **Query Parameters:**
  - `limit`: Integer (optional, default: 100) - Maximum number of properties to return.
  - `offset`: Integer (optional, default: 0) - Number of properties to skip.
  - **Response:** List of `Property` schemas.
  - **Status Codes**: 200 OK

- `GET /properties/{property_id}`
  - **Description:** Retrieve a specific property by its ID.
  - **Response:** `Property` schema.
  - **Status Codes:** 200 OK, 404 Not Found

- `PUT /properties/{property_id}`
  - **Description:** Update an existing property.
  - **Request Body:** `PropertUpdate` schema (partial `Property` schema, `date_last_updated` will be updated automatically).
  - **Response:** Update `Property` schema.
  - **Status Codes:** 200 OK, 404 Not Found, 400 Bad Request

- `DELETE /properties/{property_id}`
  - **Description:** Delete a property by its ID.
  - **Response:** No Content.
  - **Status Codes:** 204 No Content, 404 Not Found.

#### 3.2 Transaction Endpoint (`/transactions`)
- `POST /transactions`
  - **Description:** Create new transaction.
  - **Request Body:** `TransactionCreate` schema (excluding `id`, `date_created`).
  - **Response:** `Transaction` schema (include `id`, `date_created`).
  - **Status Codes:** 201 Created, 400 Bad Request

- `GET /transactions`
  - **Description:** Retrieve a list of all transactions.
  - **Query Parameters:**
    - `property_id`: String (optional) - Filter transactions by category ID.
    - `start_date`: Date (optional) - Filter transactions from this date onwards
    - `end_date`: Date (optional) - Filter transactions up to this date.
    - `limit`: Integer (optional, default: 100) - Maximum number of transactions to return.
    - `offeset`: Integer (optional, default: 0) - Number of transactions to skip.
  - **Response:** List of `Transaction` schemas.
  - **Status Codes:** 200 OK

- `GET /transactions/{transaction_id}`
  - **Description:** Retrieve a specific transaction by its ID.
  - **Response:** `Transaction` schema.
  - **Status Codes:** 200 OK, 404 Not Found
  
- `PUT /transactions/{transaction_id}`
  - **Description:** Update an existing transaction.
  - **Request Body:** `TransactionUpdate` schema (partial `Transaction` schema).
  - **Response:** Updated `Transaction` schema.
  - **Status Codes:** 200 OK, 404 Not Found, 400 Bad Request

- `DELETE /transactions/{transaction_id}`
  - **Description:** Delete a transaction by its ID.
  - **Response:** No Content.
  - **Status Code:** 204 No Content, 404 Not Found

### 3.3 Transaction Category Endpoints (`/transaction_categories`)
- `POST /transaction_categories`
  - **Description:** Create a new transaction category. 
  - **Request Body:** `TransactionCategoryCreate` schema (excluding `id`, `date_created`, `date_last_updated`)
  - **Response:** `TransactionCategory` schema (including `id`, `date_created`, `date_last_updated`)
  - **Status Codes:** 201 Created, 400 Bad Request, 409 Conflict (if category name already exists)

- `GET /transaction_categories`
  - **Description:** Retrieve a list of all transaction categories.
  - **Response:** List of `TransactionCategory` schemas.
  - **Status Codes:** 200 OK

- `GET /transaction_categories/{category_id}`
  - **Description:** Retrieve a specific transaction category.
  - **Response:** `TransactionCategory` schema.
  - **Status Codes:** 200 OK

- `PUT /transaction_categories/{category_id}`
  - **Description:** Update an existing transaction category.
  - **Request Body:** `TransactionCategoryUpdate` schema (partial `TransactionCatory` schema, `date_last_updated` will be updated automatically)
  - **Response:** Updated `TransactionCategory` schema.
  - **Status Codes:** 200 OK, 404 Not Found, 400 Bad Request, 409 Conflict (if updated name already exists)

- `DELETE /transaction_categories/{category_id}`
  - **Description:** Delete a transaction category by its ID.
  - **Response:** No Content.
  - **Status Codes:** 204 No Content, 404 Not Found, 409 Conflict (if categories are associated with existing transactions)

### 4. Data Validation and Error Handling
- **Input Validation:** Pydantic models will be used for request body and query parameter validation, ensuring data integrity.
- **Error Responses:** Standard HTTP status codes will be used (e.g. 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found, 409 Conflict, 500 Internal Server Error). Error responses will include a clear message explaining the issue.
- **Firestore-specific Errors:** Handle potential Firestore errors (e.g. network issues, permission denied, document not found during updates).

### 5. Technologies and Libraries
- **Python:** The core programming language.
- **FastAPI:** For building the API endpoints and handling HTTP requests.
- **Pydantic:** For data validation and serialisation/deserialisation of API models.
- **Google Cloud Firestore Client Library for Python:** For interacting with Firestore.
- **python-dotenv:** For managing environment variables (e.g. Firestore Project ID)
